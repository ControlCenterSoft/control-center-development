# Control Center — безопасность пользовательских сессий

## Назначение

Control Center предоставляет локальной аутентифицированной учётной записи возможность немедленно завершить все свои активные сессии. Это самостоятельная защитная операция на случай потери устройства, подозрения на компрометацию браузерной сессии или необходимости принудительно повторить аутентификацию на всех клиентах.

## API

`POST /api/v1/auth/sessions/revoke-all`

Операция:

- требует действующую аутентифицированную сессию;
- недоступна до завершения обязательной смены первоначального пароля после чистой установки;
- отзывает все активные сессии текущей учётной записи, включая сессию, из которой выполнен запрос;
- после успешного выполнения требует нового входа;
- не принимает идентификатор другого пользователя и поэтому не является административным API управления чужими сессиями;
- не возвращает и не записывает в Audit значения session token, cookie или пароля.

При cookie-аутентификации ответ также удаляет cookie текущей сессии. Успешный ответ имеет статус `204 No Content`.

## Audit и fail-closed граница

Перед изменением состояния сессий Control Center обязан успешно записать audit-событие `auth.sessions_revoke_all` со статусом `requested`. Если обязательный Audit недоступен, отзыв сессий не начинается.

После выполнения сохраняется событие `auth.sessions_revoke_all` со статусом `success` и количеством отозванных сессий. При ошибке session store фиксируется `failed` без записи чувствительных значений.

Эта операция не изменяет пароль, RBAC-привязки, Desired State или инфраструктурные ресурсы.

## Проверяемые инварианты

- две и более активные сессии одного пользователя становятся недействительными после одного успешного вызова;
- текущая сессия также отзывается;
- повторное использование отозванного token приводит к отказу аутентификации;
- невозможность записать обязательное pre-mutation audit evidence блокирует операцию до изменения состояния;
- обязательный first-login password-change boundary остаётся приоритетным и не обходится через session-control API.

Формальный HTTP-контракт находится в `api/openapi-auth-session-controls.yaml`.
